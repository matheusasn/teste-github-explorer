## O que aconteceu

### Manhã — antes de qualquer código

Recebi o PDF e tratei como **leitura crítica**, não como checklist. Antes de abrir o editor, montei o vault Obsidian de processo:

- `00-contexto/briefing-teste.md` — mapeamento técnico do PDF seção por seção, separando o que é exigência rígida (`/search/repositories`, busca + detalhe + issues, paginação, tema, erros) do que é tom (sugestões de stack, observações de "preferir X")
- `00-contexto/decisoes-iniciais.md` — padrões e referências arquiteturais que pretendo aplicar (Clean Arch Uncle Bob 2012, branded types, discriminated union, FSD no presentation, ESLint flat config com boundaries, Conventional Commits, ADRs Nygard)
- `00-contexto/meu-perfil-tecnico.md` — calibragem: lista do repertório técnico ativo e dos sinais de drift (JSDoc longo, switch+helper, `Array<T>`, ViewModels, `any` em produção)

Decisão consciente: vault **antes** de código. Sem isso, qualquer escolha posterior fica sem âncora.

Decisão de processo também tomada agora: **sem agentes Claude**. Vi o padrão "agentes-geradores por área" (domain-builder, screens-builder etc.) e rejeitei — pra 3 telas read-only, overhead de orquestração não compensa, fragmenta contexto, infla artefato. Registrei em [[03-rejeitado/agentes-claude-multiplos]].

### Tarde — Bloco 1 (Domain) + reconsideração sobre agentes

Setup do projeto: `expo init` SDK 55, TS strict + `noUncheckedIndexedAccess` + `noFallthroughCasesInSwitch`, path aliases, ESLint flat config, Husky, Commitlint, Jest, jest-expo, RNTL.

Entidades (`Repo`, `Issue`, `Owner`, `Label`), `IGitHubRepository`, erros tipados. Decisões formalizadas conforme apareceram:

- ADR 001 — Clean Arch em 4 camadas: estabelecida a Dependency Rule como invariante do projeto
- ADR 003 — Branded types pros IDs: confundir `IssueId` com `RepoId` em compile-time deixa de ser possível
- ADR 004 — Discriminated union nos erros: classe estende `Error` (preserva stack trace) + `kind` literal (habilita exhaustiveness check na UI)

10 testes do domain passando ao fim do bloco. Como o domain é Node puro, testes rodam sem `jest.mock`.

**Reconsideração sobre agentes.** Olhando o vault crescer (3 docs de contexto + 3 ADRs já registradas) e pensando em como ele sobreviveria à entrega, percebi que a rejeição da manhã mirava no formato errado: **agentes-geradores** continuam fora, mas **agentes-auditores** são uma categoria diferente — não escrevem código, validam coerência sobre código + vault já existentes.

Casa bem com o que o projeto já tem: a Dependency Rule semântica precisa de revisão (ESLint só pega imports), o perfil técnico tem lista explícita de "sinais de alerta" que só faz sentido se alguém audita, o vault em crescimento sem curadoria vira pasta morta, ADRs Nygard exigem formato repetido. Criei 4 agentes em `.claude/agents/`:

- `architecture-auditor` — fiscal da Dependency Rule
- `code-style-auditor` — caçador de drift contra o perfil técnico
- `adr-keeper` — formaliza decisão pronta em ADR Nygard
- `vault-curator` — curador do pensamento em construção (capturas, weekly review, conexões)

Formalizei como ADR 008. Nenhum agente escreve código de produção — risco de geração inconsistente eliminado.

### Noite — Blocos 2, 3, 4

**Application:** use cases (`SearchReposUseCase`, `GetRepoDetailsUseCase`, `GetRepoIssuesUseCase`) como function factories. ADR 002 formalizada — função em vez de classe elimina `this`, DI natural via closure. `InMemoryGitHubRepository` em `src/test-utils/` permite testar use cases sem mockar HTTP.

**Infrastructure:** `httpClient` (axios + baseURL + `GITHUB_API_VERSION`), `apiGet` helper, `errorTranslator` (anti-corruption layer traduzindo `AxiosError` em erro de domínio), mappers (snake_case → camelCase + branded IDs), `GitHubRepositoryImpl`, container DI manual via factory.

**Design System:** tokens (paleta GitHub-flavored), `ThemeContext` próprio, 7 componentes (Text, Button, Input, Card, Badge, Avatar, Skeleton).

Mais ADRs emergiram durante o trabalho:

- ADR 005 — Feature-Sliced dentro de `presentation/`: agrupar screen + componentes + hooks por feature em vez de pastas flat
- ADR 006 — Theme Context custom sem Restyle: tema cabe em ~120 linhas, dependência externa traria overhead injustificado
- ADR 007 — ESLint flat config com boundary rules: Dependency Rule deixa de ser convenção e vira regra enforçada no `pre-commit`
